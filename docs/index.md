# Building Filesystem Agents

Создайте файлового агента, который использует bash-инструменты и Vercel Sandbox, чтобы исследовать транскрипты звонков и отвечать на вопросы.

> Перевод интерактивного курса [Vercel Academy](https://vercel.com/academy/filesystem-agents). Авторы оригинала: **Cameron Youngblood** и **Malte Ubl**.

---

LLM обучены на огромных объёмах кода. Они провели бесчисленные часы, перемещаясь по директориям, ища по файлам с помощью `grep` и управляя состоянием в сложных кодовых базах. Агенты уже «отработали своё» и по-настоящему понимают файловые системы.

Типичный подход к контексту агента — либо запихнуть всё в промт, либо использовать векторный поиск. Заполнение промта упирается в лимиты токенов. Векторный поиск хорош для семантического сходства, но возвращает неточные результаты, когда нужно конкретное значение из структурированных данных. Файловые системы предлагают другой компромисс: структурируйте данные как файлы, дайте агенту bash — и модель применит те же способности, что использует для навигации по коду.

В этом курсе вы построите файлового агента для анализа транскриптов звонков. Тот же паттерн работает для юридических документов, агентов-кодировщиков, финансового анализа или генерации и выполнения SQL.

## Почему файловые системы работают

- **Структура соответствует предметной области.** Записи о клиентах, история тикетов, CRM-данные: у них есть естественные иерархии, которые напрямую отображаются в директории. Вы не сплющиваете отношения в эмбеддинги.
- **Точное извлечение.** `grep -r "pricing objection" calls/` возвращает точные совпадения. Когда нужно одно конкретное значение — вы получаете именно его.
- **Контекст остаётся минимальным.** Агент загружает файлы по требованию. Большой транскрипт не попадает в промт целиком. Агент читает метаданные, ищет нужные фрагменты через `grep` и подтягивает только необходимое.
- **Отлаживаемость.** Когда агент ошибается, вы видите, какие именно файлы он прочитал и какие команды выполнил. Путь выполнения виден. Никакого чёрного ящика.

## Что вы построите

Полноценного файлового агента, который работает в Vercel Sandbox, исследует транскрипты звонков с помощью bash-команд и стримит ответы обратно в чат-интерфейс. Вы будете использовать AI SDK для цикла агента и инструментов, а AI Gateway — для маршрутизации запросов к Anthropic Claude.

## Предварительные требования

Для этого проекта вам понадобятся:

- Node.js 18+
- Менеджер пакетов pnpm
- Аккаунт Vercel
- Vercel CLI
- Ключ AI Gateway API

Опыт построения агентных фреймворков не требуется.

## Как устроен курс

Курс разделён на две секции. Следуйте по порядку, потому что каждая секция строится на предыдущей.

### Секция 1: Building an Agent

Настройте проект, определите агента и создайте bash-инструмент.

- [Project Setup](01-building-agent/1a-project-setup.md) — клонируйте репозиторий, свяжите с Vercel, изучите стартовый репозиторий
- [Agent Skeleton](01-building-agent/1b-agent-skeleton.md) — определите `ToolLoopAgent` в `lib/agent.ts`
- [Bash Tool](01-building-agent/1c-bash-tool.md) — создайте `createBashTool` со схемой Zod в `lib/tools.ts`

К концу секции у вас будут определены агент и инструмент, готовые к подключению.

### Секция 2: Running in the Sandbox

Подключите песочницу, загрузите данные и протестируйте работающего агента.

- [Wire Up the Sandbox](02-running-sandbox/2a-wire-up-sandbox.md) — инициализируйте песочницу и подключите bash-инструмент
- [Files and Instructions](02-running-sandbox/2b-files-and-instructions.md) — загрузите транскрипты и добавьте инструкции агенту
- [Test and Extend](02-running-sandbox/2c-test-and-extend.md) — протестируйте с реальными вопросами, изучите расширения

К концу секции у вас будет работающий файловый агент, который исследует транскрипты звонков с помощью bash-команд.
