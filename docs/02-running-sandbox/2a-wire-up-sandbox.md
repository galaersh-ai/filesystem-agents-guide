# Урок 4: Wire Up the Sandbox

Инициализируем песочницу Vercel Sandbox и подключаем bash-инструмент к агенту, чтобы он мог безопасно выполнять команды.

## Проблема

Когда вы строите ИИ-агентов, которые выполняют код, вы, по сути, позволяете LLM запускать произвольные команды в вашей системе. Это несёт серьёзные риски безопасности:

- **Непредсказуемый вывод** — LLM могут галлюцинировать или генерировать некорректные команды, которые ведут себя неожиданно.
- **Prompt injection** — вредоносный пользовательский ввод может обмануть агента и заставить его выполнить опасные команды вроде `rm -rf /` или прочитать чувствительные файлы.
- **Истощение ресурсов** — бесконечный цикл или команда, пожирающая память, может уронить ваш сервер.
- **Утечка данных** — без изоляции агент может прочитать переменные окружения, учётные данные или приватные данные.

## Решение

Песочница предоставляет изолированную среду выполнения, которая защищает хост-систему. С Vercel Sandbox:

- Команды выполняются в отдельном контейнере без доступа к вашей реальной файловой системе.
- Сетевой доступ можно ограничить.
- Лимиты ресурсов предотвращают «убегающие» процессы.
- Даже если LLM сгенерирует опасные команды, они не затронут продакшен-окружение.

Это значит, что вы можете безопасно дать агенту мощные инструменты вроде bash-выполнения, не беспокоясь о последствиях, если что-то пойдёт не так.

### Инициализация песочницы

В `agent.ts` инициализируем песочницу над определением агента:

```typescript
// lib/agent.ts
import { Sandbox } from '@vercel/sandbox';

const sandbox = await Sandbox.create();
```

Теперь можно передать эту песочницу в `createBashTool`, чтобы создать инструмент в агенте:

```typescript
// lib/agent.ts
import { createBashTool } from './tools';

export const agent = new ToolLoopAgent({
  // ...
  tools: {
    bashTool: createBashTool(sandbox)
  }
});
```

Агент получил доступ к bash-инструменту, но в песочнице ещё нет файлов для исследования. Нужно загрузить файлы в песочницу до запуска агента — это сделаем в следующем уроке.

Полное решение `lib/agent.ts`:

```typescript
// lib/agent.ts
import { ToolLoopAgent } from 'ai';
import { createBashTool } from './tools';
import { Sandbox } from '@vercel/sandbox';

const MODEL = 'anthropic/claude-opus-4.6';

const sandbox = await Sandbox.create();

export const agent = new ToolLoopAgent({
  model: MODEL,
  instructions: '',
  tools: {
    bashTool: createBashTool(sandbox)
  }
});
```

## Ключевые выводы

- `Sandbox.create()` — асинхронный, поэтому используйте top-level `await` (поддерживается в серверных модулях Next.js).
- Песочница должна создаваться до определения агента, так как агенту нужен инструмент на этапе конструирования.
- Имя ключа в объекте `tools` (`bashTool`) — это то, что «видит» LLM, поэтому оно должно быть описательным.
- Ключевые угрозы без песочницы: непредсказуемый вывод, prompt injection, истощение ресурсов и утечка данных.

## Попробуй сам

1. Перезапустите dev-сервер (`pnpm dev`) и откройте `http://localhost:3000`.
2. Спросите агента: **«list the files in the current directory»**.
3. Посмотрите на ответ. Вы должны увидеть, как агент вызывает `bashTool` с командой вроде `ls`:

```
[bashTool] $ ls
```

Вывод покажет корневую директорию песочницы — она почти пустая, потому что файлы ещё не загружены.

!!! note "Пустая песочница — это ожидаемо"
    Если агент выполнил `ls` и показал минимум вывода — это правильно. Песочница — свежий контейнер без пользовательских файлов. В следующем уроке вы загрузите в неё транскрипты звонков.
