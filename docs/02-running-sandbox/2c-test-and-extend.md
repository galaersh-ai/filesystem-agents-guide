# Урок 6: Test and Extend

Тестируем готового агента реальными вопросами и разбираем направления для расширения: новые инструменты, источники данных и возможности UI.

## Проблема

Агент готов, но «готов» не значит «проверен». Нужно убедиться, что он корректно справляется с разными типами вопросов, и понять, как он использует bash в каждом случае. А ещё — понять, куда двигаться дальше: как добавлять инструменты, улучшать конвейер данных и UI.

## Решение

Запустите dev-сервер с помощью `pnpm dev` и откройте `http://localhost:3000` в браузере. Задайте вопрос вроде **«how did the deal progress?»** или **«did they mention pricing?»** и наблюдайте, как агент работает, перемещаясь по файловой системе.

### Тестируем агента

Попробуйте эти категории вопросов и заметьте, как агент использует bash по-разному для каждой.

**Discovery-вопросы** — проверяют, может ли агент ориентироваться в файловой системе:

- «What files are available?»
- «How many calls are there?»
- «What's in the calls directory?»

Агент должен использовать `ls` и, возможно, `wc` для ответа. Наблюдайте за вызовами инструментов — агент сам разбирается в структуре файловой системы.

**Summarization-вопросы** — проверяют, может ли агент читать и синтезировать содержимое:

- «Summarize the first call»
- «What were the main topics across all calls?»
- «Who are the participants in call 2?»

Агент обычно выполняет `cat` для одного или нескольких файлов и выдаёт структурированную сводку. Для вопросов по нескольким файлам он может читать каждый файл последовательно.

**Search-вопросы** — проверяют способность находить конкретную информацию:

- «Did anyone mention pricing?»
- «Were there any objections raised?»
- «What action items were discussed?»

Следите за использованием `grep`. Агент должен искать по файлам, а не читать всё подряд. Именно здесь паттерн «файловая система как контекст» блистает: агент использует bash как язык запросов.

!!! tip "Наблюдайте за вызовами инструментов"
    Чат-интерфейс отрисовывает каждый вызов `bashTool` с командой и её выводом. Это ваше окно в «рассуждения» агента — вы видите, какие именно команды он выполняет и в каком порядке.

## Ключевые выводы

- Цикл инструментов: `prompt → tool call → result → next tool call → final response`.
- Разные типы вопросов задействуют разные bash-команды: `ls`/`wc` для ориентации, `cat` для сводки, `grep` для поиска.
- Агент использует bash как язык запросов к данным — это и есть суть файлового подхода к контексту.

## Попробуй сам

### Идеи расширения

**Добавить инструменты** — дайте агенту новые возможности:

- **File upload tool** — пусть пользователи загружают документы динамически вместо предзагрузки.
- **Search tool** — семантический поиск по документам через эмбеддинги.
- **Write tool** — позвольте агенту создавать сводки или отчёты и сохранять их.

**Улучшить конвейер данных:**

- Загружайте файлы из облачного хранилища (S3, Vercel Blob) вместо локальной файловой системы.
- Подключите базу данных, чтобы запрашивать структурированные данные рядом с транскриптами.
- Добавьте инструмент, который получает файлы по требованию, а не предзагружает всё.

**Улучшить UI:**

- Добавьте сохранение истории чата в базу данных.
- Покажите дерево файлов, доступных в песочнице.
- Добавьте аутентификацию для ограничения доступа.

**Использовать пакет `bash-tool`** — он абстрагирует сложность записи и чтения файлов из файловой системы и бесшовно интегрируется с Vercel Sandbox и AI SDK.

### Проверка готовности

- Вы протестировали агента discovery-, summarization- и search-вопросами.
- Вы увидели, как агент использует разные bash-команды для разных типов вопросов.
- Вы понимаете цикл инструментов: `prompt → tool call → result → next tool call → final response`.
- Вы просмотрели идеи расширения и представляете, что строить дальше.
